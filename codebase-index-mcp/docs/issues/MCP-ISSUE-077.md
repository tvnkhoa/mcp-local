## MCP-ISSUE-077 — HTML entry pages and SVG assets were not nodes, so "who uses icon.svg" had no answer

- **Status:** ✅ FIXED 2026-10-20 (release F item 14 of the wec.aria adoption plan).
- **Scenario:** wec.aria's 5 `.html` pages were `unknown_extension`, its 61 `.svg` files were dropped by the `assets/` path rule (and `.svg` was an excluded extension), and `.png` / `.pdf` were reported as `excluded_extension` alongside text files. No tool could name the page that loads `src/main.ts`, or the components that render a logo.
- **Fix:**
  - **HTML** (`extractors/htmlExtractor.ts`, language `html`): module symbol plus `IMPORTS import:<spec>` for `<script src>`, `<link href>` (any rel), `<img src>`, `<source src>`, `<use href|xlink:href>`, `<image href>`. Remote / `data:` / `#` / templated (`%BASE_URL%`, `{{ }}`) values and commented-out tags are skipped; `?query` / `#fragment` are cut; root-absolute `/src/main.ts` is relative to the page (Vite's root), and a root-absolute static asset (`/favicon.svg`) is looked for under `./public/`; only targets the index can hold get an edge.
  - **SVG** (language `svg`): a module-only asset node; the minified rule lifted; the `assets/` / `public/` / `static/` segment exclusion lifted for `.svg` only (`isExcludedByPath`). Usage edges: a TS/JS `import x from "./icon.svg"` was already an `IMPORTS` token and now resolves (`resolveModuleSpecifier` cuts `?raw` / `?url` / `#frag`); a Vue template's static `src` / `href` / `xlink:href` with a `.`, `~` or `@` prefixed `.svg` URL becomes `IMPORTS` from the component (`vueTemplate.emitAssetImport`) — what Vue's `transformAssetUrls` compiles it to.
  - **`IMPORTS`, not a new `USES_ASSET` type**: the bundler compiles each of these references into a module import, so it is one; the shared import resolver binds it with no new pass; and every IMPORTS consumer (`find_impact_files` importedBy, `get_dependency_graph`, circular-dependency detection, `get_file_summary`) answers "who uses icon.svg" unchanged. A new type would need its own resolver, traversal-list entries and health accounting for a relation the existing one already means.
  - **`binary_asset`**: png / jpg / gif / ico / webp / avif / bmp / tiff / pdf / office documents / fonts / audio-video / archives / native binaries are skipped with that reason wherever they sit (checked before the path rule, in `shouldIndexFile` and in the scan's path tally).
- **Live** (wec.aria, same run as 076): 5 `html`, 61 `svg` files. `packages/portal/index.html → packages/portal/src/main.ts`; its `/theme-boot.js` stays an unresolved token (the file is `public/theme-boot.js`, and `.js` under `public/` is not indexed). Who uses `wecrm-horizontal-dark.svg`: `SignIn.vue` and `SelectTenant.vue` (`find_impact_files`, 0.95 "resolved relative import"); `wecrm-mark-white.svg`: `AppSidebar.vue`. 5 svg usage edges, 0 unresolved `.svg` tokens. `binary_asset .pdf` 3; the 199 png/jpg are gitignored and reported as such.
- **Guarded:** `textLanes.test.ts` (HTML references, `localAssetSpec`, Vue template asset imports), `fileFilterReleaseF.test.ts` (svg segment lift, binary assets); `test:html-svg` (32 checks, real MCP stdio): html/svg languages and module-only symbols, the page's three resolved references and no edge for CDN / commented / png, icon.svg used by a `.ts` import (incl. `?raw`) and a `.vue` template `src`, a sprite `#fragment`, no edge for a root-absolute template URL, skip reasons, separators, I1 = I2 = 0, incremental = full.
- **Not done here:** CSS `url(…svg)`, `:src` bindings and `new URL('./x.svg', import.meta.url)` are not edges. Root-absolute `.js` under `public/` (wec.aria's `theme-boot.js`) is not indexed, so its page edge stays a token.
