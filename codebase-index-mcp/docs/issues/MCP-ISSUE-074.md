## MCP-ISSUE-074 — R2 Vue: `.vue` files were skipped, so no tool could say who renders a component

- **Status:** ✅ FIXED 2026-10-20 (release E item 9, Vue lane stages 1–3, of the wec.aria adoption plan).
- **Scenario:** wec.aria's 188 `.vue` files (vue 3.5, `<script setup lang="ts">`, explicit imports) were skipped as `unknown_extension`. "Who uses `ReadFailure.vue`" / "who uses `AppCard.vue`", an `@event` handler, and a component used only in a template were all invisible: a handler bound only through `@click` had no caller, so it read as dead.
- **Fix:**
  - **Language `vue`** in `LANGUAGE_BY_EXTENSION` and `inferLanguageFromPath` — its own tag, not `typescript`, because `files.language` is what `search_regex` / `dead_code_scan` filter on and a `.vue` file is template + script + style.
  - **Blocks** (`extractors/vueSfc.ts`): `@vue/compiler-sfc` 3.5.44 (exact pin, pure JS, loaded lazily on the first `.vue` file; the same 3.5.44 `compiler-dom`/`shared` that `@vue/language-core` 3.3.11 resolves, so one copy is installed; wec.aria runs vue ^3.5.41). The split keeps file coordinates and exposes `styles` (content, start line, `lang`, `scoped`, `module`) — the CSS lane's hook, now wired.
  - **Script**: both script blocks go through the unchanged TS lane on a copy of the file with everything else blanked (same length, same line breaks), so every row — and therefore every `makeSymbolId` — is the real `.vue` row with no offset arithmetic. The comment/citation scanners read the same mask (`maskVueToScripts`).
  - **Component** (`extractors/vueExtractor.ts`): a new kind `component`, one per file (name = file name, row 0). `defineProps` (type literal, same-file `interface`/`type`, runtime object/array, `withDefaults`), `defineModel` (`modelValue` + `onUpdate:modelValue`) and `defineEmits` (call signatures, 3.3 shorthand, runtime array/object) become `property` children; an event is registered under the listener key Vue compiles it to (`close` → `onClose`). `emit('x')` in script and `$emit('x')` in a template are `CALLS` to that member; `props.x` is `PROPERTY_REF`. The macros' own `callee:defineProps`-style tokens are removed (compiled away, never callable).
  - **Templates** (`extractors/vueTemplate.ts`, the compiler-dom AST): a new edge type **`USES_COMPONENT`** from the component to `component:<specifier>`, bound after the run by `graph/edgeResolverComponents.ts` through the shared `resolveModuleSpecifier` (kebab tags, `<Form.Item>`, every imported `<component :is>` branch). Gaps are kept and labelled, never dropped: a dynamic `:is` branch (`vue dynamic :is branch not resolvable to an import`), an un-imported tag (`vue tag not imported (global or auto-registered component)`), a bare package specifier (`external boundary`), a binding the child does not declare (`vue binding not declared by child (fallthrough attribute)`). Intrinsic `:is` strings (`'div'`) are ignored. `:prop`, static attributes, `@event` and `v-model` on a child are `PROPERTY_WRITE` to the child's member with the bound text as `assignedExpression` (Vue compiles a listener to the `onX` prop). Expressions are parsed with the TS grammar: calls → `CALLS` (a same-file handler directly, with `vue template … (line N)` in `reason` since edges have no line column), `a.b` → `PROPERTY_REF property:b`, own-prop reads → `PROPERTY_REF`; `v-for` / `v-slot` / arrow parameters are scoped out.
  - **Cross-tool**: `USES_COMPONENT` is in `CALL_TRAVERSAL_EDGE_TYPES` (`get_call_chain`, `trace_execution_flow`, `find_impact_files`); `dead_code_scan` counts `USES_COMPONENT` and an `IMPORTS` of the component's file (router `() => import()`, `createApp(App)`) as use, and `App.vue` is a bootstrap file; `find_implementations` on a component returns `notApplicable`; `search_symbols` ranks `component` like `class`. `component:` joins the placeholder lists (`UNRESOLVED_SYMBOL_TOKEN_PREFIXES`, dedupe, the cross-repo pass, `getUnresolvedStats`). `USES_COMPONENT` (and the two CSS edge types) are exempt from the confidence floor like `TYPE_REF`: the `large` profile's 0.4 floor deleted every 0.2 gap — found by the harness.
  - **CSS hook**: each `<style>` block goes through `extractCss` at `startLine - 1`; template `class="a b"` and literal `:class` (strings, arrays, object keys, ternary/logical branches) become `USES_CSS_CLASS`. A dynamic class expression is not emitted (its name is not knowable from the text).
  - `INDEX_VERSION` → `v6-vue-components`.
- **Live** (wec.aria, full run of the built lane into a temp DB, 0 parse failures): 188 `.vue` files indexed (2048 files, 12 402 symbols, 41 158 edges, 26.6 s; the pre-change build: 1 860 files, 9 554 symbols, 26 564 edges, 18.4 s). `get_file_summary(packages/portal/src/App.vue)`: 7 symbols (module, component, 4 `css_class`, 1 `css_variable` — its script declares only computed bindings). 576 `USES_COMPONENT` resolved; 1 692 prop/listener writes resolved, 49 labelled fallthrough; 11 un-imported tags (`RouterView`, `RouterLink`, …), 1 dynamic `:is` gap. Who uses `ReadFailure.vue`: 20 components (`ChunkPane`, `RetrievalDoctor`, `SelectTenant`, …) plus a test import. Who uses `AppCard.vue`: 28 components, including `RetrievalDoctor.vue` and `VersionFacts.vue`. `@submit="ask"` in `packages/console/src/AskRow.vue:39` → `ask` at `AskRow.vue:30`. `--text-tertiary` (2 definitions, `colors.css:150/251`): 44 `.vue` files' `<style>` rules use it. `dead_code_scan(language: "vue")`: 41 candidates (14 components — the `checks/*/violations` samples nobody renders — 24 functions, 3 variables); counting no template use, 188 components and 215 functions would have had no caller.
- **Guarded:** `vueSfc.test.ts` (6 tests: block order/lines/lang/setup, style hook, malformed input, masks, real lines through `extractGraphData`); `test:vue-components` (42 checks, real MCP stdio): language/kind/lines, runtime and interface props, macro noise, `USES_COMPONENT` incl. kebab tags and per-branch `:is`, labelled gaps, prop/listener/`v-model` writes, handler and inline-call lines, `$emit`/`emit`, own-prop reads, CSS var/class users, `find_impact_files`, `get_call_chain`, `dead_code_scan` (template-only components and handlers are live; an unrendered component and an uncalled function are listed), `find_implementations`, `search_regex(language: "vue")`, incremental parity after AppCard's lines shift.
- **Not done here:** exact field references inside `.vue` (Volar, R3 — `typeResolution/`). Script-setup refs/computeds are not symbols, so a template read of one is no edge. A template's own read of a member path (`row.kb_id`) is a bare `property:` token resolved by name with the existing honest labels. Pug templates and SCSS/Less `<style>` blocks are skipped. Globally registered components resolve only as labelled gaps.
