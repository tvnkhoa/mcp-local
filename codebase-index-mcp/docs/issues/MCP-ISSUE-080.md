## MCP-ISSUE-080 — R11: no tool answered "which tests does my uncommitted change need, and how do I run them"

- **Status:** ✅ FIXED 2026-10-21 (release G item 12 of the wec.aria adoption plan, R11).
- **Scenario:** after editing `packages/core/audit/index.ts` in wec.aria, the agent had `link_tests_to_source(filePath)` (pairs for ONE file, name-heavy, default `minScore` 0.4) and `change_impact` (a committed range or the unstaged diff, ranked `risk × link score` — the 0.076 the wec.aria reviewer saw). Neither followed the import graph out of the changed files, neither knew that `@aria/core/audit` is a workspace-package import of that file, neither said which vitest config would pick a test up, and a changed TEST file came back as "no linked test" for itself.
- **Tool/query attempted:** `link_tests_to_source(repoId, filePath)`, `change_impact(repoId)`.
- **Expected vs actual:** expected the tests reaching the diff, each with its reason, and one runnable command per package; got name-ranked pairs, sub-threshold suggestions and no command.
- **Fix:** `link_tests_to_source(repoId, forWorkingTreeDiff: true)` (exclusive with `filePath`; without it the pair listing is unchanged):
  - **Diff:** `readWorkingTreeState` — the one `git status --porcelain=v2 -z --untracked-files=all` read the R1 freshness gate uses (staged, unstaged, untracked, both sides of a rename), re-rooted with `rev-parse --show-prefix` when `repoPath` is a subdirectory. The freshness gate has already dirty-indexed those files when the handler runs.
  - **Closure** (`services/analysis/testDiffGraph.ts`, `testsForDiff.ts`): reverse BFS over file → file `IMPORTS` and `USES_COMPONENT` edges, plus bare imports of the repo's own workspace packages. The import resolver leaves `@aria/core/audit` an `import:` token (a package name is not a path), so it is mapped here through the target package's `package.json` `exports` (conditions in default / import / types order, `./*` patterns, longest prefix), or `main` / `index` without `exports`; the package set is the `npm:<name>` module signatures behind MCP-ISSUE-076's workspace `DEPENDS_ON` edges. A subpath no `exports` entry names maps to the whole package and is reported (package-level: over-reporting, never missing). Bounded by `maxDepth` (6, ≤ 12) and `maxFiles` (2000, ≤ 20 000): a depth stop names the files one hop further (coverage `medium`), a file-cap stop drops coverage to `low`. The package → package `DEPENDS_ON` edges themselves are not walked: a manifest dependency says nothing about which file imports which, and walking it would list every test of every dependent package.
  - **Tests:** runnable test files reached (`isTestPath` plus a `.test.` / `.spec.` / `test_*.py` / `*Tests.cs` name — helpers under `test/`, like console's `render.ts`, are walked through and counted in `supportFilesReached`, not listed); every dirty test file (`why: "changed itself"`, depth 0); and name/score links. `linkTestsToSource` runs with NO floor so the floor is applied once, here: `score >= minScore` (default **0.7** in this mode — the schema default was removed so the pair listing keeps 0.4) is listed with `why: "name link score …"`; anything lower is dropped and counted in `belowMinScore` (pairs whose test is not otherwise listed). Each test: `why[]`, `depth`, `chain` (parent → … → changed file).
  - **Run plan** (`testRunPlan.ts`, `vitestConfig.ts`; nothing is executed): package manager from the root lockfile (`pnpm-lock.yaml` → pnpm; `corepack` when the root `packageManager` names it); package = nearest `package.json`; config = vitest's own `findUp` from the package dir over `vitest.config.*` then `vite.config.*` (a vite config without a `test` block = vitest defaults), then `vitest.workspace.*`. The config is read **lexically**: comments stripped, the outermost object holding `test:` found by string-aware brace matching, only literal strings / arrays / objects taken (`defineConfig` / `defineProject` / function-form configs included). An identifier, spread, call or `${}` template is named (`include: identifier base`) and the package dir is used instead. `include` / `exclude` (vitest 4 defaults when absent) and inline `test.projects` are matched with minimatch against the path relative to `root` (`test.root` / `root`, resolved against the run dir as vitest's `resolve(root)` does); a test no config admits goes to `excluded` with the reason (`excluded by "**/*.dom.test.ts" in packages/core/vitest.config.ts`). One command per (package, config, root): `corepack pnpm --filter <pkg> exec vitest run <files relative to root>` (yarn `workspace … exec`, npm `exec --workspace=`), `npx vitest run --root <dir> <files>` without a package name. A file importing `node:test` gets `runner: "unknown"` and a `node --test <file>` hint; other non-vitest tests get `runner: "unknown"` and no command.
  - **Routing:** `orient`'s `tests` rule now recommends `link_tests_to_source(forWorkingTreeDiff: true)` first for an uncommitted change, and `change_impact` for a committed range.
  - **Coverage:** `knownGaps` names a depth or file-cap stop, changed code files the index does not hold, unresolved relative imports whose name (stem, or the folder of an `index` file) matches a changed file, package-level workspace hops, and unreadable configs.

- **Not done here:** configs are never executed, so an `include` built from variables, a `mergeConfig` of an imported base, or a `projects` entry held in a variable is a named gap with the package-dir fallback, not an answer. Path-glob projects defer to the matched package's own config (defaults when it has none). Non-vitest runners (jest, mocha, pytest, `dotnet test`) get no command. `change_impact` keeps its `risk × score` ranking with no floor — unchanged here. A deleted test file is reported `changed itself` + `deleted` and kept out of the commands.

- **Follow-up 2026-10-21 (wec.aria acceptance, before the G report): no package-manager command.** The run plan emitted `corepack pnpm --filter <pkg> exec vitest run …`. In wec.aria running pnpm rewrites tracked config (`storeDir`) and creates an untracked store in a worktree other sessions share — a measured failure mode, and why that repo forbids pnpm — so an agent copying the command would dirty everyone's tree. Every command is now the package's own binary from the package directory, `cd <pkg dir> && ./node_modules/.bin/vitest run [--root <r>] <files>`, in every repo; the detected package manager stays in `runPlan.packageManager` as information only. `testRunPlan.test.ts` asserts no command names pnpm/yarn/npm/npx/corepack. Also from that review: `change_impact` lists an edited test as `changed itself`, carries `linkScore` beside the risk-weighted `score`, and defaults `testLinkMinScore` to 0.7 (the reported 0.076 was a 0.76 link on a 10%-risk file).
