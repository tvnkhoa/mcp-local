## MCP-ISSUE-083 — `orient` sent the R4 / R5 / R9 / R11 questions to the wrong first tool

- **Status:** ✅ FIXED 2026-10-21 (release I2 of the wec.aria adoption plan).
- **Scenario:** the tools for wec.aria's requirements landed (R4 `query_docs{mode:"term"}`, R5 `{mode:"cites"}`, R9 `get_cross_repo_impact{direction:"inbound"}` over endpoint contracts, R11 `link_tests_to_source{forWorkingTreeDiff:true}`), but `orient` — the static keyword table an agent asks first — did not route to them. It ranked rules by the number of single phrases hit, so a question naming two things lost to whichever one-phrase rule shared a word with it.
- **Tool/query attempted:** `orient(intent)` with the reviewer's 16 phrasings (4 per requirement, English and Vietnamese).
- **Expected vs actual** (the pre-change table, run on the 16 phrasings): 2 of 16 right — the two R11 phrasings that contain `which tests` / `what tests`. Ten fell to the generic fallback (`search_symbols`), including "tests for my diff", "who cites decision #737", "canonical name for proposed_tag_change", "who calls the wec.be endpoint /customers/global-search" and all four Vietnamese ones. The rest went to the wrong tool: "where is kb_version_ids defined in docs/10" → `search_symbols` (`where is`); "which docs/10 section defines tenant_id" and "what references adr/0021" → `query_docs{mode:"search"}` (`which doc`, `adr`); "what breaks in Aria if VehicleController.GetListOwnedVehicle changes" → `find_impact_files` (same-repo; `what breaks`); "impact of changing a wec.be controller action on other repos" → `get_cross_repo_impact` but `direction:"outbound"` — the wrong way for "who consumes this action".
- **Fix** (`services/analysis/orient.ts`, still a pure function of the string — no LLM, `guard:no-llm-runtime` passes):
  - **Compound rules**, matched before the keyword table and ranked ahead of it in table order: one signal from EVERY group. Generic shapes, no repo names: `tests-for-diff` (tests/spec × uncommitted, diff, edited, just changed, my/current change, working tree, thay đổi, vừa sửa, chưa commit); `doc-citations` (cite/references/citations/trích dẫn × `#N`, `adr/NNNN`, `docs/N`, a `.md` file, decision, `SPEC-N`); `doc-term` (define/canonical/registry/glossary/tên này/định nghĩa × `docs/N`, canonical, registry, glossary); `endpoint-consumers` (endpoint, controller, route, a `/route/path` × breaks, who calls, callers, consumers, impact, affect, other repo(s), cross-repo, hỏng, ai gọi, ảnh hưởng).
  - **Seeds** into the first tool's arguments: R9 the last two-hump segment of the first PascalCase/camelCase identifier (`VehicleController.GetListOwnedVehicle` → `name: "GetListOwnedVehicle"`), else a route path as a placeholder plus `route_map` second; R4 the first snake_case token (or a backticked name) as `query`; R5 `filePath` for "what does X cite", else `target` (`docs/15 #116`, `adr/0021`, `SPEC-037`, `decision #737`, a `.md` path).
  - **Diacritics folded** before matching: NFD, combining marks stripped, `đ` → `d` (a letter, not a mark); so "trích dẫn" = "trich dan".
  - Caveats carried with the rule: R9 — a shared name answers through the one endpoint-contract carrier or returns `ambiguous` with every candidate, and the consumer repo is indexed after the provider; R11 — the per-package commands are returned, nothing executed; R5 — `target` uses the repo's own citation shorthand (wec.aria writes a decision as `15 #737`, so `decision #737` matches no pattern and is tried as a path); R4 — `query` is matched exactly against the registry rows' first cell.
- **Kept:** every keyword rule and its order. "which tests" (no diff word) keeps the `tests` rule, whose first entry was already `forWorkingTreeDiff:true`; "who calls fooBar" (no endpoint word) stays the fallback; "rename …", "blast radius of changing file …", "what breaks if I change parseConfig", "list endpoints", "where is the definition of …", "which doc describes the decision record" route as before.
- **Live** (built server over MCP stdio, `orient` without repoId): all 16 first tools as required — R9 `get_cross_repo_impact {"direction":"inbound","name":"GetListOwnedVehicle"}`, `{… "name":"<the action serving /customers/global-search>"}`, `{… "name":"GetHistory"}`, `{"direction":"inbound"}`; R11 `link_tests_to_source {"forWorkingTreeDiff":true}` ×4; R4 `query_docs {"mode":"term","query":…}` with `kb_version_ids`, `proposed_tag_change`, `claim_kind`, `tenant_id`; R5 `query_docs {"mode":"cites",…}` with `target` `decision #737`, `adr/0021`, `docs/15 #116` and `filePath` `CLAUDE.md`.
- **Guarded:** `orient.test.ts` — the 16 phrasings verbatim (first tool, key argument, seed), the Vietnamese ones without diacritics, and 11 regression phrasings for the keyword rules.
- **Not done:** `decision #N` is not rewritten to a repo's shorthand (orient has no repo config); a route-path seed is a placeholder, not resolved to its action (that is `route_map`'s job, listed second).
