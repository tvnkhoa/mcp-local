## MCP-ISSUE-073 — R3 exact: TS/JS fields answered by the TypeScript LanguageService, not a lower bound

- **Status:** ✅ FIXED 2026-10-20 (release D item 8 of the wec.aria adoption plan; follows MCP-ISSUE-067, which made the graph answer honest but could only call it a lower bound). `.vue` exact (Volar) and the two release D acceptance notes: follow-up below, same day. Programs built in a worker thread (release I1): follow-up below, 2026-10-21.
- **Scenario:** `find_field_accesses(repoId: "wec.aria", name: "kb_version_ids")`. The field is a key of the field bag `audit_event_common_fields` (`contracts/src/entities/audit-event.ts:23`), spread into four `z.strictObject`s under `audit_event_schema`. The same name is also an api function (`api/src/wire/envelope.ts:103`) and console's own `ConsoleReply.kb_version_ids` (`console/src/reply.ts:218`).
- **Expected vs actual (before):** expected every read and write of the contract field. Got `property: null`, `coverage: "low"` — honest since 067, but no answer: the TS/JS graph lane has property edges only for `this.<member>`.
- **Two facts the R3 spike measured, which shape the fix:**
  - The real writer, `core/audit/index.ts:92`, is `audit_event_schema.parse({ … kb_version_ids … })`. `.parse` takes `unknown`, so the literal has no contextual type and no type-based reference finder links it. Without a dedicated pass the tool reports "no writer in core" for a field core writes on every turn.
  - Homonyms are the common case, not noise. Resolution must be per declaration, not per name.
- **Fix:** `src/services/typeResolution/` (TS/JS only).
  - `languageServiceHost.ts`: one LanguageService per repo, lazy, LRU of 2, keyed by the latest index run id (a new run re-reads the root files and re-stamps snapshots by mtime; only changed files re-parse). Root files = the repo's indexed TS/JS files minus `node_modules`, `dist`, `dist-runtime`, `violations/`, `coverage`, vite/vitest configs. The host supplies `realpath` (pnpm) and adds no `customConditions` (wec.aria's `aria-runtime` would resolve to stale `dist/`).
  - **Simplification (documented in the module):** one union program per repo with the options of the repo's base tsconfig (`tsconfig.base.json` → `tsconfig.json` → `jsconfig.json`), plus `allowJs`, `checkJs: false`, `noEmit`, `composite: false`, and an empty `types: []` dropped. Not one program per tsconfig as tsserver would build.
  - `fieldDeclarations.ts`: property-like candidates are Zod shape keys, keys of a module-level field bag spread (directly or via another bag) into a Zod shape, property signatures, class properties and accessors. Functions, variables, methods and types of the same name are **named non-matches**.
  - `fieldReferences.ts`: candidates grouped by `findReferences` (a field-bag key and its `z.infer` property, or an interface and its implementer, are one group); every reference classified DEFINITION / WRITE / READ (`fieldClassify.ts`, the spike's classifier).
  - `zodParsePass.ts`: for `X.parse | safeParse | parseAsync | safeParseAsync (arg)` whose X reaches a Zod shape (`.shape`, union `.options`, wrapper `_def`) declaring the field in the group — checked through the checker, so spreads count and another schema's same-named key does not — the literal's key, or the key of an identifier argument's object-literal initializer, is a WRITE `viaParse`. Any other argument (parameter, call result) is a named gap.
  - Gaps, by file: `.vue` files mentioning the name (Volar lane later), unfollowable parse arguments, dynamic `obj[key]` on a type declaring the field (checked in files that reference the group or name its owner or a type declared beside it).
  - `caps.ts`: one budget per answer (`CODEBASE_INDEX_TS_LS_COLD_START_MS`, 60 000) and an RSS ceiling (`CODEBASE_INDEX_TS_LS_MAX_RSS_MB`, 2 500). The LS cancellation token aborts `findReferences` between files; program construction is synchronous inside TypeScript, so a slow build is caught when it returns. A breach is coverage `"gap"` and **no list**; a memory breach also drops the program.
  - **Homonym policy:** one candidate group → its answer. Several and no pick → `candidates` with exact per-candidate read/write counts and no site list; re-ask with `declarationFile` (+ `declarationLine`) or `ownerName` (schema, bag, interface or class name; a field bag also answers to the schemas it is spread into). A `symbolId` in a TS/JS file picks by its file and line.
  - `find_field_accesses` uses the lane when `CODEBASE_INDEX_TS_LS_ENABLED` (default true) and the field is TS/JS: a TS/JS `symbolId`, or a name with no exact-name property outside TS/JS. C# keeps the receiver-typed graph answer. A stale index lowers `exact` to `high`. `typescript` moved to `dependencies`, pinned 5.9.3.

The cold program build blocks the server's event loop (8-24 s on wec.aria); a worker-thread host would remove that.
- **Follow-up 2026-10-20 — `.vue` exact (Volar) and two release D acceptance notes.**
  - **Vue in the program** (`src/services/typeResolution/vueProgram.ts`). `@vue/language-core` 3.3.11 and `@volar/typescript` 2.4.28 are dependencies, pinned exactly (pure JS; the versions the R3 spike used, = wec.aria's vue-tsc set), loaded lazily only for a repo with `.vue` files. **Decision: a second, Vue-aware program per repo, not the union program** — a Vue package compiles under different options (vue-tsc's reading of its tsconfig, DOM libs, `module: preserve`, `moduleResolution: bundler`, `vite/client` types), and under the union program's `nodenext` a `./X.vue` import does not even resolve. Options come from the tsconfig owning the most `.vue` files (nearest `tsconfig.json` above each SFC; the base tsconfig when none is nearer), parsed with `createParsedCommandLine`, plus `allowNonTsExtensions` / `allowJs` / `noEmit`; other Vue-owning configs are assumed compatible (wec.aria's console and portal are). Roots = every `.vue` + the TS/JS roots under those configs' directories; contracts come in through imports. Host wiring the spike found: `getScriptKind` → `Deferred` for `.vue`, `resolveModuleNameLiterals` present for Volar to wrap, `allowNonTsExtensions`. Same `AnswerBudget` (both programs' builds and every `findReferences` count against `CODEBASE_INDEX_TS_LS_COLD_START_MS` / `_MAX_RSS_MB`; a breach is still `gap` and no list). Same invalidation: a new run re-plans and re-stamps snapshots in place. No new env var.
  - **Classification.** Each union-program group is re-asked in the Vue program; hits come from the UNPROXIED LanguageService in Volar's generated code and are mapped with `toSourceRanges(…, isReferencesEnabled)` to real `.vue` offsets, then classified by the same `fieldClassify` on the generated AST (template `entry.f !== null` → READ "property-access (template)", enclosing `<template>`; `row.f = null` in `<script setup>` → WRITE "assignment" in its function). `.vue`-declared props (`defineProps<{ f: … }>()`) are candidate groups of their own (owner `"X.vue props"`). Zod parse pass, dynamic access and untyped keys also run over `.vue`. An unmapped generated hit (a `v-if` repeated inside an event handler) is a gap only when its file has a mention no mapped site accounts for; otherwise it is counted in `typeResolution.vue.unmappedGenerated`.
  - **Fallback = the old named gap**, with the reason: plugin unavailable; **`vue language-core major mismatch (ours X, repo Y)`** (repo version read-only from `node_modules/@vue/language-core|vue-tsc` under the Vue configs and the root, then `pnpm-lock.yaml` / `package-lock.json` / `yarn.lock`; unknown ≠ mismatch); `'vue' does not resolve` (without Vue's types every template expression is `any` and its references vanish — the lane refuses instead of reporting an empty `.vue` list as exact); a `.vue` Volar produced no TypeScript for.
  - **Acceptance note (1), freshness vs `exact`.** `applyFreshness` appended "index not current: … This answer comes from the previous index." to `coverage.knownGaps` of an `exact` answer. The LanguageService reads every file from disk, so the sites ARE current; only the program's file list is index-derived. For a TypeScript-lane payload the note now stays out of `coverage`, the "previous index" clause is dropped from its reason, and `freshness.appliesTo` names the index-derived part.
  - **Acceptance note (2), untyped same-name keys** (`untypedKeys.ts`). Object-literal keys named like the field whose literal has no contextual type declaring it (absent, `any`/`unknown`, or no union member with the property), and that are not already a site / declaration / parse write, are `nonMatches` of kind `"untyped-object-key"` with the enclosing name. Text-prefiltered files, one checker call per same-named key.

- **Follow-up 2026-10-21 (release I1) — the programs are built in a worker thread.** The "Not done" above: the cold build (union program 2 768 files + Vue program 949 files on wec.aria) was synchronous, so the first field query held the server's event loop for 10-20 s and every other tool call waited behind it.
  - **Design.** The whole field answer — both programs, `findReferences`, the Vue pass, the Zod parse pass, the gap scans, the untyped-key scan — runs in one worker per process (`src/services/typeResolution/fieldWorker.ts`, spawned lazily by `fieldWorkerClient.ts` with `new URL("./fieldWorker.js", import.meta.url)`, so the two stay in one folder). The server thread posts `{repoId, repoPath, runKey, relativeFiles, field, pick, caps}` and receives the serialisable `FieldAnswer`; it no longer loads TypeScript at all. The LanguageService LRU, the run-key invalidation and every answer rule are unchanged — they now live in the worker's heap. `find_field_accesses` and `query_docs{mode:"term"}` became async; nothing else changed shape.
  - **Wait budget = the R1 query budget** (`CODEBASE_INDEX_QUERY_REFRESH_BUDGET_MS`, default 5 s; no new env var). A call that the worker has not answered by then returns coverage `gap`, `breach.kind: "building"`, the reason `type program still building for '<repo>' (n s so far)` (or "worker is starting (loading TypeScript)") and NO list. The request stays queued, so the build carries on; its late answer is kept (keyed by repo, run id, field, pick and caps — within one run the LanguageService answers from the same snapshots) and served to the next identical call. Identical calls in flight share one request (a caller polling through a cold build no longer stacks copies of its query behind it — the harness measured that starving every poll before the fix); at most 8 distinct requests are outstanding, beyond that a call is withheld at once.
  - **Caps.** `CODEBASE_INDEX_TS_LS_COLD_START_MS` still bounds the answer inside the worker; a watchdog terminates a worker 30 s past it (program construction is not cancellable). `CODEBASE_INDEX_TS_LS_MAX_RSS_MB` now measures the worker: its V8 heap (used + external + malloced) at the phase checks, and the same figure is the worker's `resourceLimits.maxOldGenerationSizeMb`, so V8 terminates the worker — never the server — if the heap gets there first. Either breach is coverage `gap` (kind `memory`) and the worker is discarded; the next field call spawns a fresh one. `typeResolution` reports `workerHeapMb`, `mainHeapMb` and `roundTripMs` beside the process `rssMb`.
  - **Live** (worktree build, wec.aria @ `c64ed243` with 4 dirty files, full index into a temp DB: 2 902 files, 0 parse failures; fresh server per phase):

  - **Guarded:** `fieldWorkerClient.test.ts` (5 tests over a fake worker: a withheld `building` answer with no list and the late answer served to the next identical call; identical calls share one request; a memory breach discards the worker and the queued call is withheld too, the next call respawns; V8 out-of-memory → memory gap; the queue bound). `test:field-access-worker` (new harness: a 600-file generated fixture whose cold build takes ~5 s; with a 300 ms wait budget, `search_symbols` answers in < 1 s during the build, the concurrent field call answers within budget + 1 s as a gap with no list, polling reaches exact with the complete counts, a warm round trip < 0.5 s; a 48 MB cap returns a memory gap with no list and `search_symbols`/`health_check` keep answering, also after a second field call). `test:field-access-exact`, `test:field-access-vue`, `test:docs-term` unchanged and passing.

The program is built on the first field query, not pre-warmed at start-up or after an index run. The relative file list (~2 900 paths) is sent with every request.
