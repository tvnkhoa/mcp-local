## MCP-ISSUE-089 — a doc mention several symbols matched equally was bound to the first by path

- **Status:** ✅ FIXED 2026-10-22 (release K4, 883e6b9; D1 option (B) of release J).
- **Scenario:** `resolveMentions` keeps, per name, the symbols of the best kind rank; when several remained it took the first. Release J made that pick deterministic (canonical order: path, line, id) — still a pick. On wec.aria 6 593 backtick and 46 `code_call` mentions were bound that way, and `query_docs stale` then named one arbitrary symbol (`HoldPreview` → the contracts type; every doc means the `.vue` component).
- **Tool/query attempted:** a replay of the resolver over wec.aria's stored mentions and symbols (`k4measure.mjs`, work file).
- **Expected vs actual:** expected "ambiguous, N candidates"; got one candidate stated as the answer.
- **Fix:**
  - Rule: a backtick / `code_call` mention is decided by the first step with a candidate — exact name, lower-case name, a dotted symbol's last segment, a dotted symbol's leading part; the name steps keep the best kind rank (class < interface < function < method < variable < other). The deciding step having MORE than one candidate leaves `symbol_id` NULL. The dotted-prefix step was first-wins too and gets the same rule; the suffix step already refused ties (MCP-ISSUE-049) and now records them. filepath → module symbol (release J) and doclink are unchanged.
  - Storage: `doc_mentions.candidate_count` and `candidate_ids` (JSON, canonical order). The WHOLE list is stored, not the first 20 of the design note: `stale` matches a changed symbol against it, and a cap would drop the docs whose mention lists that symbol 21st. Measured: 6 769 ambiguous rows, 53 507 ids, max 135 candidates, 1.45 MB on wec.aria. Responses show at most 20.
  - Readers, each saying "ambiguous" rather than naming one symbol or nothing: `query_docs stale` also lists a doc whose ambiguous mention has a changed symbol among its candidates (`match: "ambiguous"`, `candidateCount`, `ambiguousRows` + note); `coverage` / `get_file_context` add `ambiguousMentionCount` per symbol (not in `mentionCount`/`hasDocs`); `drift` excludes ambiguous rows (they are not missing) and reports `ambiguousExcluded`; `search` with symbols lists `ambiguousMentions: [{mentionText, ambiguous: true, candidateCount}]`; doc freshness (`behind`) reports `ambiguousMentionsSkipped`.
  - Unbound and ambiguous rows are re-decided by every run; a scoped run unbinds only the bound rows it can have changed (MCP-ISSUE-088 P3).
  - `INDEX_VERSION` → `v12-release-k`.
