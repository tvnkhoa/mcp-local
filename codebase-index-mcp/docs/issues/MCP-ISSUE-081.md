## MCP-ISSUE-081 — R9: no edge said which wec.be controller action an Aria tool calls

- **Status:** ✅ FIXED 2026-10-21 (release G item 11 of the wec.aria adoption plan, R9).
- **Scenario:** wec.aria's MCP adapter calls wec.be over HTTP. The routing table (`packages/core/adapters/mcp/wecrm-routes.ts`) binds tool names to `SourcedRoute` consts whose `path` is a function the graph cannot run — but since 520f729a every production row also declares a static `source: 'wecrm:GET /dealer/customers/{id}/history'`. Nothing read it, so `get_cross_repo_impact` on `CustomerController.GetHistory` could not name the Aria tool that breaks when the action changes.
- **Tool/query attempted:** `get_cross_repo_impact(repoId: "wec.be", symbolId: <GetHistory>, direction: "inbound")`.
- **Expected vs actual:** expected the Aria route, its file:line and its tool; got nothing — no TS edge pointed at an endpoint, and the tool queried only the action symbol, while cross-repo endpoint links target the endpoint CONTRACT symbol minted next to it.
- **Fix:**
  - **Extractor** (`services/extractors/jsHttpConsumers.ts`, called from the JS lane): an object literal with a string-literal `source: '<scheme>:<METHOD> /<path>'` (verbs GET/POST/PUT/DELETE/PATCH; a computed or template-with-`${}` source is ignored) emits `DEPENDS_ON endpoint:METHOD:/path`, confidence 0.9, from the route const's `variable` symbol (or the table holding an inline row, else the enclosing symbol / module). Reason `http consumer (<scheme>) route=<binding> tool=<tool>`: `tool` is a sibling `tool:`/`name:` string or an inline row's property key.
  - **Id format: unchanged.** The id is minted by `toEndpointContractId` — the function the C# controller lane uses (lowercased path, one leading slash, parameter segments verbatim: `{id}`, `{customerid}`, `{id:int}`). Parity is a unit test. wec.be does NOT need a re-index for the id.
  - **Matcher** (`services/graph/endpointMatch.ts`, used by `resolveUnlinkedEdges` for endpoint tokens with no exact provider): tier 1 `exact`; tier 2 `wildcard` — same method and segment count, literals equal, a parameter segment matches any parameter segment and never a literal, trailing slash and ASP.NET `~/` normalised; tier 3 `gateway_prefix` — declared consumers only (`http consumer (` reasons), the consumer's first one or two literal segments stripped, the shortest strip wins, linked only when exactly one provider contract matches (else counted `unresolved_ambiguous`). First tier with a candidate wins.
  - **Why tier 3 exists:** wec.be's controllers do not declare `/dealer`. `CustomerController` is `[Route("customers")]`; the gateway (`src/services/gateway/CRM.Gateway/ocelot.json`) maps upstream `/dealer/{everything}` to the customer service's `/{everything}`. Without tier 3 all three Aria routes stay unmatched tokens. The gateway config itself is not parsed (the downstream host → project mapping is a naming convention, not data); the match is labelled and the stripped prefix reported.
  - **`get_cross_repo_impact`:** a method or controller symbol expands to the endpoint contract symbols minted for its routes (same file, route line); new `filePath` input queries every symbol of a file; rows carry `relatedLine`, `targetName`, and for endpoint links an `endpoint` block (`consumerEndpoint`, `providerEndpoint`, `matchKind`, `strippedPrefix`, `scheme`, `route`, `tool`, `toolSource`, `toolDeclaredAt`) and `resolutionReason` `endpoint_contract_wildcard_match` / `endpoint_contract_gateway_prefix_match`. When the route literal names no tool, the files importing the route file (≤ 20, ≤ 512 KB each, inside the repo root) are scanned for `<tool>: <routeConst>` — `toolSource: "routing_table"` with the file:line. A provider queried outbound, or inbound with no consumer, gets a `hint`. The `edgeReason` join now also matches an exact contract token.
  - `route_map` and `find_impact_files` do not read `cross_repo_deps`; unchanged.
  - `INDEX_VERSION` → `v8-http-consumers` (a consumer repo needs a run to emit the edges).

  The first live run (before the shortest-strip rule) left `GetHistory` unlinked as ambiguous: stripping two segments also matched CRC's `endpoint:GET:/{callid}/history` (`CRCController.CallNote.cs:29`, no class route). Two more consumers surfaced and are correct by the rule: `envelope` in `packages/core/test/turn-candidates.test.ts:28` and `turn-next-steps.test.ts:16` declare the global-search source in test fixtures, so `SearchCustomerGlobal` lists them too (reason without route/tool).
- **Guarded:** `jsHttpConsumers.test.ts` (template-typed `SourcedRoute` consts incl. `satisfies`, missing/computed/non-HTTP sources ignored, inline table rows with key and `tool:`, id parity with a C# controller fixture, reason round-trip); `endpointMatch.test.ts` (tiers, parameter-vs-literal refusal, catch-all, trailing slash, `~/`, gateway bounds, shortest strip); `runPolicy.test.ts` (generation 8); `test:http-consumers` (37 checks, real MCP stdio, one DB: C# repo with `[Route("dealer/customers")]` `global-search` / `{customerId}/history` / `{customerId}/notes`, `[Route("dealer/vehicles")]`, `[Route("orders")]` `{id:int}` and a root `{slug}` decoy; TS repo with three sourced route consts, a routing table in another file, an inline row with `tool:` reached through a gateway prefix, and an unmatched `POST /dealer/tasks`): inbound per action by symbol and by file with route, file:line, tool and match kind; no false link to `{customerId}/notes`; the outbound hint; outbound from a route const; the unmatched token labelled and counted no_candidate; stable links over a second full run.
- **Not done here:** links are written by the CONSUMER's run only — index the provider first, or re-index the consumer after the provider (a provider re-index also re-mints its endpoint symbol ids, which leaves the consumer's rows dangling until the consumer runs again; this is the existing cross-repo behaviour, not new). The Ocelot gateway map is not read, so tier 3 is a labelled inference that would mislink if two services served the same remainder under different gateway keys (it then refuses as ambiguous only if both match at the same strip depth). The routing-table tool lookup is a bounded text scan at query time, not a graph edge. Path parameters inside a segment (`file-{id}.json`) and catch-all segments are not wildcarded.
