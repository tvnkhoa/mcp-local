## MCP-ISSUE-075 — CSS lane: design tokens and classes were invisible to the graph

- **Status:** ✅ FIXED 2026-10-20 (release E item 9, CSS bullet, of the wec.aria adoption plan; the `.vue` `<style>` and template half lands with the Vue lane).
- **Scenario:** "who uses `--text-tertiary`" on wec.aria. `.css` had no entry in `LANGUAGE_BY_EXTENSION`, so every stylesheet was skipped as `unknown_extension`: `search_symbols("--text-tertiary")` found nothing and no tool could name a user of a design token.
- **Fix:**
  - `services/extractors/cssExtractor.ts`, on `postcss` 8.5.29 (pure JS, exact pin), not tree-sitter. `extractCss(source, { repoId, filePath }, lineOffset, { scoped })` is pure, so the Vue lane calls it per `<style>` block with `lineOffset = blockStartLine - 1`; `scoped` is recorded in the signature.
  - Two symbol kinds. `css_variable`: one symbol **per definition site**, because `:root` and a dark-theme override are different values and go-to-definition must list both. `css_class`: one symbol **per name per file** at its first rule, with the rule count in the signature, because a class is styled by many rules and consumers refer to it by name. Names keep the `--` / `.` so a class `foo` can never become the target of a JS call `foo()`; FTS still finds `.card-title` by `card-title`.
  - `USES_CSS_VAR` (new edge type, not `TYPE_REF`/`PROPERTY_REF`, which carry C#/TS meaning other tools read): from the custom property being defined (`--a: var(--b)` is `--a → --b`), else the rule's subject class (walking out through nested rules), else the module. The target is always the token `cssvar:<name>`.
  - `USES_CSS_CLASS` (new edge type) for markup uses, emitted by the Vue lane; this lane provides `classNamesFromStatic(classAttr)` and `cssClassToken(name)` (`cssclass:.name`).
  - `@import` → `IMPORTS import:<spec>`, resolved by the shared import resolver; a remote URL (`https://`, `//`) is tagged `external boundary` at extraction.
  - Post-phase `resolveCssEdges` (`graph/edgeResolverCss.ts`): binds each token by name repo-wide and **fans it out to every definition** (`resolved css variable by name`, 0.9; `… (N definitions)`, 0.8). It also re-fans earlier resolutions, so an incremental run that adds a definition lands on the same graph as a full run. A name with no definition is kept as `unresolved css variable token` at 0.5, never dropped. `cssvar:` / `cssclass:` are in `UNRESOLVED_SYMBOL_TOKEN_PREFIXES` and skipped by the cross-repo pass; they are not counted in `unresolvedRatio`, a code-graph health signal.
  - Both CSS edge types are in `CALL_TRAVERSAL_EDGE_TYPES`, so `get_call_chain(direction:"callers")` and `find_impact_files` answer "who uses".
  - `dead_code_scan` excludes `css_variable` and `css_class` outright: markup, `classList`, `style.setProperty` and third-party templates use them where the graph cannot see, so no incoming edge proves nothing.
  - `INDEX_VERSION` → `v5-css-lane`. A syntax error throws and counts as a parse failure. SCSS/Less are not parsed.
- **Live** (wec.aria, full run of the built lane into a temp DB, 18.7 s, 0 parse failures): 7 `.css` files (all `packages/portal/src/styles/`), 366 `css_variable` symbols (246 names), 7 `css_class`; 197 `USES_CSS_VAR` edges (144 to names with 2 definitions), 0 unresolved `cssvar:` tokens; the one `@import` is Google Fonts (now `external boundary`). `--text-tertiary` has 2 definitions (`colors.css:150` `:root`, `:251` dark theme) and **no `.css` user**: its users are `.vue` `<style>` blocks, which arrive with the Vue lane.
- **Guarded:**
  - `cssExtractor.test.ts` (9 tests): definition sites, per-file classes, nested rules, `@media`, `@keyframes`, comments, multi-line values, escapes, owners, `@import` forms, remote imports, line offsets and ids, `scoped`, syntax errors, the helpers.
  - `test:css-symbols` (20 checks, real MCP stdio): search by `--text-tertiary` / `.card-title` / `card-title`, `get_file_summary`, `get_call_chain` from both definitions, `find_impact_files` (files and surface) reaching a file linked only by `var()`, the labelled unresolved token, `@import`, `dead_code_scan`, and full-vs-incremental equality after a definition is appended.
- **Not done here:** template `class` / `:class` edges and `<style>` blocks (the Vue lane calls `extractCss` and `classNamesFromStatic`). A stylesheet's own class mentions are not edges: it styles a class, it does not use it. SCSS/Less, `@layer` order and cascade specificity are out of scope: every definition is a candidate.
