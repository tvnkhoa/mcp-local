## 3. Key decision: workspaces are scoped to `packages/*` only

The four servers are **deliberately excluded** from the `workspaces` array.

The migration plan (S-07/S-09) identified workspace hoisting versus
`codebase-index-mcp`'s native dependencies — `better-sqlite3`, four tree-sitter
grammars, and the platform-pinned `sqlite-vec-windows-x64@0.1.9` — as the single
most likely cause of migration failure, and required a throwaway spike before
committing.

Scoping the workspace to `packages/*` sidesteps that entirely for now:

- Each server keeps its own `package.json`, `package-lock.json`, and
  `node_modules`. Their installs are byte-for-byte untouched.
- Only the five new packages resolve through the root `node_modules`.
- No server dependency is hoisted, so no native module changes how it loads.

**Verified consequence:** all four servers still typecheck and build. A root
`node_modules` now exists and sits later in Node's resolution chain than each
server's own, which is why nothing shifted.

Bringing the servers into the workspace remains migration-plan step S-09, still
gated on the S-07 spike. **This foundation does not force that decision.**

## 4a. Code review — 13 findings, all fixed

An adversarial review of the foundation raised 13 findings. I reproduced six of
them against the built code before changing anything; all reproduced exactly as
described. Every one is fixed, and each has a regression test.

### Security-relevant

| # | Finding | Fix |
|---|---|---|
| 1 | **Read-only SQL guard bypass via Postgres dollar-quoting.** `stripStringsAndComments` knew `'…'`, `"…"`, `--`, `/* */` but not `$$…$$` / `$tag$…$tag$`. An apostrophe inside a dollar quote opened a phantom string that swallowed the rest of the statement. Verified: `SELECT $$'$$; DROP TABLE t` → **ALLOWED** | Scanner now handles dollar quotes, `E'…\'…'` escape strings, and reports unterminated literals — which are refused outright, since a scanner that could not see the whole statement cannot vouch for it |
| 2 | **Upstream response body returned to the client.** `mapStatusToError` put a 512-byte `bodyPreview` into `details`, which `toPayload()` serializes to the caller. A 401 body commonly echoes the submitted token | `details` now carries status/statusText only; the body is logged at debug level, where the redactor sees it |
| 3 | **URI credentials never redacted.** `postgres://admin:S3cretPass@host` passed through `redactObject` verbatim, under any key and in free text | New `maskUriCredentials`, applied to **every** string. Scheme, user and host survive — masking the whole URL would destroy the diagnostic value; the password is the secret |
| 4 | **Non-idempotent requests retried.** Retry keyed only on status, so a 503 on `POST /pulls` issued 3 POSTs — duplicate PRs from one call | Only GET/HEAD/OPTIONS retry automatically; anything else must set `idempotent: true` explicitly |
| 5 | **Per-request `authorization` silently discarded.** `options.authHeader` was applied after the request-header spread, so it always won | Client credential now sits before the per-request spread, so a caller can override it deliberately |

### Correctness

| # | Finding | Fix |
|---|---|---|
| 6 | **`normalizePayload` corrupted repeated references.** `seen.add` with no matching delete made the WeakSet detect *shared* references, not cycles. A graph payload reusing a node inside an edge — exactly what `codebase-index-mcp` emits — serialized as the string `"[circular]"` | `seen.delete` on exit, so `seen` tracks the ancestor chain. True cycles are still caught |
| 7 | **Same bug in `redactValue`**, losing the second mention of an object in a log record | Same fix |
| 8 | **`dispatchToolCall` could reject**, contradicting its "nothing throws out of here" contract: the `asError` calls sat outside the `try` and used raw `JSON.stringify` on caller-supplied `details`. A BigInt threw out as a protocol failure | Whole body wrapped; `asError` routes through `serializePayload`; `asFatalError` is a hand-written last resort that cannot itself throw |
| 9 | **Array holes were dropped, reindexing the array.** `[1, undefined, 3]` → `[1, 3]`, so element *n* no longer matched element *n* of the source | Holes become `null` |
| 10 | **Regex metacharacters in policy tokens unescaped.** A natural denylist entry like `pg_read_file(` threw `SyntaxError`, turning every query into a crash rather than a rejection | Tokens escaped; word boundaries applied only where the token starts/ends with a word character |
| 11 | **Boolean enums advertised as `"type":"string"`** | `enumOf` branches on `boolean` too |

### Tooling gaps

| # | Finding | Fix |
|---|---|---|
| 12 | **The `process.env` rule never ran on any server.** The check sat inside the `packages/*` loop, so the `/src/config.ts` allowlist entries were dead code and the drift the guard exists to prevent went unchecked | The server loop now performs the env check. See the severity note below |
| 13 | **Test files were never type-checked.** Every package tsconfig excludes `*.test.ts`, and `node --import tsx --test` strips types without checking them — so ~1,000 lines of contract-asserting code was unverified | New root `tsconfig.test.json` + `npm run typecheck:tests`, wired into `verify:packages`. It passes clean |

### Guard severity: migrated vs. pre-migration scope

Fixing #12 surfaced 34 genuine violations in the four servers (scattered
`process.env` reads, five files over the 600-line hard cap, `console.log`
calls). Those are the pre-migration debt the platform exists to remove — real,
but not caused by this change, and failing the build on them would block work
that did not create them.

So findings are now scoped:

- **`packages/*` findings keep their real severity.** The foundation must be
  perfectly clean: `guard all --strict` exits 0.
- **Server findings are downgraded to warnings.** They are reported, counted,
  and visible — `guards: 0 error(s), 34 warning(s) across 282 files` — and
  `--strict` makes them blocking, which is exactly migration-plan step S-41.

That number is now a tracked baseline to drive to zero, which is what warn mode
was for.

## 5. Two real defects the tests caught during construction

Both were in code I had just written and believed correct. Recording them
because they are exactly the class of bug the shared layer exists to eliminate
once rather than four times.

### 5.1 A 404 was being retried

`mapStatusToError` built upstream failures with the `upstream_error` factory.
That code defaults to `retryable: true`, so a 404 inherited it and the client
burned all its retries on a resource that will never appear.

**Fix:** retryability is now derived from the HTTP status, never from the error
code's default. 404 maps to `not_found`, 401/403 to `unauthorized`, all
non-retryable.

### 5.2 A secret-leak path in error normalization

`toPlatformError` put the original error's message into `details`:

```ts
details: { originalName: value.name, originalMessage: value.message }
```

`PlatformError.toPayload()` serializes `details`, and dispatch returns that to
the caller. Any thrown error whose message embedded a connection string or token
would have been handed straight to the client.

**Fix:** the original message goes on `cause` only — logged, never serialized.
`details` carries just the error class name. The regression test asserts the
secret appears nowhere in the response.

## 6. Guard findings, and the false positives fixed

On first run the guards reported 10 errors against the foundation itself. Five
were real and five were scanner defects:

**Real (fixed by writing the missing files):** all five packages lacked a
`README.md`, which package convention P7 requires.

**False positives (fixed in the scanner):**

1. **Import-like text inside string fixtures.** `cli.test.ts` contains
   `'export { c } from "@mcp/sdk";'` as *test data*; the regex read it as a real
   import and reported a tier violation. Same for `` `Deep import "${specifier}"` ``
   inside a template literal in `dependencyGuard.ts`.
   **Fix:** `from`/bare-import patterns now require the line's code to begin with
   `import`/`export`/`}`/`*`; lines whose code begins with a quote are skipped;
   and specifiers containing `$`, `{`, `}`, backticks, or whitespace are
   discarded as implausible module names.

2. **`process.env` mentioned in a comment and in the guard's own regex.**
   **Fix:** comments are stripped before the check, and the two guard source
   files that must name the pattern are allowlisted.

3. **A 415-line test file tripped the 400-line soft cap.** Test length tracks
   case count, not production complexity.
   **Fix:** test files are exempt from the soft cap; the hard cap still applies.

The scanner is regex-based and dependency-free by choice — a parser would be
more precise, but a false positive costs a two-second read, whereas a permanent
runtime dependency in the tooling tier does not go away. That trade-off is
documented in `packages/cli/README.md`.

## 7. A pre-existing failure this work did **not** cause

`npm run mcp:doctor` reports `observe-mcp` → `start: FAIL (code 1)`.

**Cause:** `observe-mcp` is registered in `~/.claude.json` as
`observe-mcp-ssdev_au` and `observe-mcp-wecrm_au_prod` — two instances under
different keys — but the manifest declares the key `observe-mcp`.
The doctor finds no config under that key, so it passes no environment, and the
server correctly fails fast:

```
PolicyViolationError: No OpenObserve credentials configured.
Set OBSERVE_AUTH_BASIC, or OBSERVE_USERNAME + OBSERVE_PASSWORD.
```

This is the manifest-key drift the Phase 0 audit flagged, and the fail-fast is
**server convention S6 working as designed**. It is unaffected by this change:
`observe-mcp` typechecks and builds, and nothing in `packages/` participates in
how the doctor spawns it.

The doctor also warns `skill not installed` for all four servers — expected,
since generated skills are gitignored and machine-specific.

**Not fixed here** (both are out of "infrastructure only" scope): the manifest
key mismatch belongs with step S-40, and multi-instance registration is a
manifest modelling question the manifest does not currently express.

## 11. Worked example — what migrating a tool will look like

Not done, and not to be done yet. Included so the next step is concrete, using
`bitbucket-mcp` (the S-23 pilot: smallest server, 8 tools, no native deps).

```ts
// bitbucket-mcp/src/tools/listRepositories.ts   — one file per tool
import { ok } from "@mcp/core";
import { annotations, defineTool, schema } from "@mcp/sdk";
import { z } from "zod";

export const listRepositories = defineTool({
  name: "list_repositories",                    // unchanged — contract is frozen
  description: "List repositories in the configured workspace. …",
  input: z.object({ role: z.enum([...]).optional(), profile: z.string().optional() }).strict(),
  inputSchema: schema.object({                  // copied verbatim from today's ListTools
    role: schema.enumOf(["owner", "admin", "contributor", "member"]),
    profile: schema.profile()
  }),
  annotations: annotations.readRemote(),
  handler: async (input, ctx) => ok(await client.listRepositories(input))
});
```

```ts
// bitbucket-mcp/src/server.ts
createMcpServer({
  name: "bitbucket-mcp",
  version: "0.1.0",
  tools: [createHealthCheckTool({ … }), listRepositories, /* … */],
  legacy: legacyBridge          // anything not yet converted keeps working
});
```

The order that keeps each step low-risk:

1. Commit the current `tools/list` output to `contracts/` (**S-06**) — before
   touching anything.
2. Add the coexistence adapter with an **empty** registry (**S-31**). Every tool
   still falls through to the existing switch; `contract:verify` must pass.
3. Move tools in small batches, verifying the contract after each.
4. Delete the legacy switch once the registry owns everything (**S-33**).

The contract must not move. `snapshotTools`/`diffSnapshots` in `@mcp/testing`
exist to make any drift a test failure.

## 12. Risk and rollback

**Rollback is R1/R2 — delete a directory and revert two files:**

```bash
git checkout -- package.json package-lock.json
rm -rf packages tsconfig.base.json tsconfig.json node_modules
# each server's own node_modules and package-lock are untouched
```

No server dependency, config, or source file participates in this change, so
there is nothing else to restore. `~/.claude.json` was never written to.

**Residual risks:**

| Risk | Assessment |
|---|---|
| Root `node_modules` shadows a server dependency | **Verified not happening** — all four still typecheck and build. Each server's own `node_modules` resolves first |
| Shared code drifts from the server copies before migration | **Real and expected.** These packages are unused today, so the four `responseFormatter` copies remain the live code. The window closes as Phase E sub-steps B/C land |
| `@mcp/shared` siblings could import each other | Convention only, not yet mechanical. Needs a per-directory rule in `guard:deps` |
| `@mcp/sdk` behaviour differs subtly from a server's hand-rolled dispatch | Unknown until the S-23 pilot. This is exactly why the pilot is the smallest server and why `contract:verify` comes first |
| Guard scanner false negatives | Regex-based; may miss exotic import forms. Findings are a floor, not a ceiling |

**The most important property:** because every extraction stopped at sub-step A,
nothing in this change can break a running server. The packages are inert until
something imports them.
